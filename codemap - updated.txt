# Voidcraft code map

Line numbers are for the current uploaded copies of `voidcraft.py` (3,427 lines) and `engineui.py` (10,140 lines), checked on 2026-11-07. They drift as you edit, so each entry also gives a name to search for.

## How the files fit together

- **`voidcraft.py`** is the game: settings menu, HUDs, the three tools, TNT and blast effects, scans, the G monitor, the main loop. It runs inside the engine host and imports the engine with `import voidcraft_engine as _E` (plus a long `from voidcraft_engine import (...)` list, lines 52 to 63, mirrored by the `requires` list in `GAME`, lines 65 to 134).
- **`engineui.py`** is the host plus the whole engine:
  - lines 1 to 558 are the launcher window (`gui`) that picks and starts a game;
  - lines 560 to 10133 are the engine, stored as one raw string `_ENGINE_SRC = r'''...'''` between `# ===== ENGINE BEGIN` (line 559) and `# ===== ENGINE END` (line 10134).
- **`engineui.py` line = engine line + 559.** Python errors in engine code report the engine's own line numbers, so add 559 to find the spot in `engineui.py`.
- `py_compile` does not check the engine string. Export it (`python engineui.py --export-engine engine.py`) and compile that instead. The engine must never contain a triple single quote.
- Do not scroll lines 4124 to 6770 of `engineui.py`: they are the embedded material textures (base64, `_TILE_PNG`).
- Two more files belong to the scanner and are not part of the game: `scanner_server.py` (Flask server on the laptop, 715 lines) and `scanner.html` (the phone page, 381 lines). The only link to the game is the `.cells` file the server writes and the game reads (see "Scans" below).

## Scans (phone to game)

1. `scanner.html` (phone) talks to `scanner_server.py` (laptop). Routes: `/api/upload`, `/api/demo`, `/api/guided/start`, `/api/job/<id>`, `.../slot/<angle>`, `.../build`, `.../frame/<n>`, `.../model/<v>`, `.../edit`, `.../import`, `/api/jobs`, `/api/about`, `/qr.svg`, `/connect`.
2. In the server, `shape_from_frames` (line 140, still the placeholder: one frame, inflated) and `build_model` (190) make the cell columns. **Import** (route at 669) writes `<name>_<id>_v<n>.cells` to the export folder (`EXPORT_DIR`, line 43, `--export`).
3. The `.cells` file is JSON, format `voidcraft.cells.v1`: `cubes_per_block`, `size`, `materials` (wood, dirt, stone, leaf, concrete), `cells` as `[x, y, thickness, material]` columns.
4. In the game, `ScanLibrary` (voidcraft.py 2675) lists every `.cells` file in `SCAN_DIRS` (2609: game folder, current folder, `scans/`, `~/Downloads/scan_exports`). `load_scan` (2625) turns a file into a material grid at the current cube detail, and `spawn_scan` (2647) stands it 4 blocks ahead via `_stand_structure`. The SCANS tab calls `place_scan` (2805) in `run()`.
